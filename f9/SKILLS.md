# SKILLS.md — f9 Feature Overview

สรุปความสามารถ/ฟีเจอร์ของระบบ f9 (Mobile Pre Booking / Invoice System — ข้อความที่ผู้ใช้เห็นใช้คำว่า "Pre Booking" แทน Pre Order/POS; ชื่อภายใน เช่น route `pos`, คอลัมน์ Orders `Pre Order No` คงเดิมโดยตั้งใจ) แยกตามโมดูล — ดูรายละเอียดสถาปัตยกรรมโค้ดที่ `CLAUDE.md`

## สิทธิ์ผู้ใช้งาน (Roles)
- **Admin**: เข้าถึงทุกเมนู แก้ไขข้อมูลทุกตาราง จัดการตั้งค่าระบบ เห็นข้อมูลสดเสมอ (ไม่ผ่าน cache)
- **Manager**: เห็นข้อมูลทุกสาขา แก้ไขออเดอร์ได้เฉพาะสถานะออเดอร์ เข้าหน้ารายงาน/เป้าได้
- **Sales**: เห็น/บันทึกได้เฉพาะสาขาตัวเอง ใช้งานหน้า POS เป็นหลัก

Login มีระบบ "จดจำ Username/Password" (เก็บใน localStorage เครื่องนั้นๆ), rate-limit 5 ครั้ง/5 นาทีกันเดารหัสผ่าน

## หน้า POS / การจอง (Checkout)
- เลือกสาขา/ช่องทางขาย → เลือกสินค้า (ค้นหา/กรองตามหมวดหมู่+ความจุ+ราคา) → เพิ่มตะกร้า
- ระบบของแถมอัตโนมัติตาม GiftMappings (ผูกกับ Model/Product Group + Channel) และโปรโมชั่น Auto Bundle
- จำกัดสินค้าหมวด "โมบาย" ได้ 1 เครื่อง/ออเดอร์ (บังคับฝั่ง server)
- ฟอร์มข้อมูลลูกค้า: ชื่อ/เบอร์/อีเมล/บัตรประชาชน, ค้นหาลูกค้าเก่าจากเบอร์โทร (auto-fill), เลขที่ Pre Order, รอบรับเครื่องลูกค้าวันที่ (ช่วงวันที่พิมพ์อิสระ), รหัสลงทะเบียน (Code Handraiser)
- ช่องบัตรประชาชน/พาสปอร์ตตรวจรูปแบบทั้งสองฝั่ง: เลข 13 หลักต้องผ่าน checksum (mod 11) ของบัตรประชาชนไทย, พาสปอร์ตรับ 6–9 ตัวอักษร A-Z/0-9 (`validateIdCard` ฝั่งหน้าเว็บ, `normalizeIdCard_` ฝั่ง server)
- ประเภทสิทธิ์การจอง (จอง T มัดจำจริง / จอง F สวมสิทธิ์แคมเปญ) พร้อมเลขที่ใบเสร็จ+จำนวนเงินมัดจำ
- พิมพ์ใบจองหลังยืนยัน — เดสก์ท็อป: popup + print dialog ปกติ; มือถือ/แท็บเล็ต (จอ ≤1024px): สร้างไฟล์ PDF ดาวน์โหลดตรง (ใช้ html2canvas + jsPDF)

## หน้าร้าน (Storefront บนหน้า POS)
- ธีมกรมท่า + ส้ม รองรับโหมดมืดและมือถือ ป้ายแถบหัวร้านใช้คำว่า **Pre Booking** (เดิม Flash Sale)
- แถบกรองด้านข้าง: เฉพาะพร้อมขาย, หมวดสินค้า, ซีรีส์/รุ่น, ช่วงราคา (ปุ่มสำเร็จรูป + ต่ำสุด/สูงสุดเอง), ความจุ, สี — เลือกได้หลายค่า (ค่าในกลุ่มเดียวกัน = OR, ต่างกลุ่ม = AND) พร้อมเรียงตามราคา/แบ่งหน้า
- ตัวกรอง/คำค้น/หน้า ถูกเก็บใน URL (แชร์ลิงก์ได้ ปุ่มย้อนกลับใช้ได้) ผ่าน `google.script.history`
- การ์ดสินค้า: ช่วงราคาของรุ่น, ประหยัดไปเท่าไร, จุดสี/ความจุเลือกได้บนการ์ด, **กดจุดสีแล้วเห็นจำนวนคงเหลือของสีนั้น**, ปุ่มเทียบสเปคและรายการโปรด
- **แนะนำซื้อคู่**: หลังเพิ่มสินค้าหลักมีกล่องเสนอสินค้าเสริม (ตามกติกา AutoPromotions + จัดอันดับตามซีรีส์/ชื่อรุ่น) และส่วนแนะนำในตะกร้า; ป้ายส่วนลดตรงกับที่ตะกร้าคำนวณจริง
- ช่องทางสินค้า `ALL` / `*` / `ทั้งหมด` = ทุกช่องทาง (ยกเว้นหมวดของแถมที่ไม่โชว์เป็นการ์ดขาย); ไม่มีสินค้าให้ช่องทางนี้ = ขึ้นข้อความแทนภาพโครงโหลด
- ติดตามใบจองสาธารณะ: ลิงก์ `?track=ORD-...` เปิดหน้าสถานะได้ (server ส่งค่าให้หน้าเว็บ เพราะ iframe ของ GAS มองไม่เห็น query ชั้นนอก) พร้อมบัตร QR Pass
- **ลิงก์สินค้าแชร์ได้**: เปิดหน้าต่างสินค้ารุ่นไหน URL จะมี `?p=<Model>` มีปุ่ม "คัดลอกลิงก์" (ใช้ URL `/exec` จาก `ScriptApp.getService().getUrl()` → `window.__APP_URL`); ลิงก์ `?p=` พาไปหน้า Pre Booking แล้วเปิดรุ่นนั้นหลังล็อกอิน, ปุ่มย้อนกลับปิดหน้าต่าง; server ตัด `<` `>` `&` ตัวควบคุมออกจากค่า `p` (กัน script injection) และจำกัด 120 ตัวอักษร
- **ไอคอนหมวดหมู่** (ไทล์หมวดสินค้าบนหน้าแรก) และชั้น **"ยอดนิยมตอนนี้"** (รุ่นที่ถูกจองมากสุดช่วง 7→30→365 วัน แคช 30 นาที ส่งแค่ชื่อรุ่น ไม่มีตัวเลข/ข้อมูลลูกค้า)
- แถบสต็อกบนการ์ดสินค้า (ยาวตามจำนวนคงเหลือ สั้น = ใกล้หมด)
- **Footer**: ปีปัจจุบัน, ลิงก์ด่วน (ติดตามใบจอง/เทิร์นเครื่อง), ข้อมูลติดต่อร้าน (โทร/LINE/เวลาทำการ จากหน้าตั้งค่า), ปุ่มกลับขึ้นบน (มุมขวาล่างเหนือปุ่มตะกร้า)

## จัดการสินค้า (Products)
- ตารางแอดมินมาตรฐาน (ค้นหา/กรอง/เรียง/export CSV) — ทุกคอลัมน์รวม Marketing Model, Price, Original Price
- **เพิ่ม/แก้ไขสินค้าแบบหลาย SKU**: กรอกข้อมูลร่วม (Model *, Marketing Model *, ความจุ *, Product Group, หมวดหมู่, ราคา, ราคาเดิม, รูปเริ่มต้น, ช่องทางขาย) ครั้งเดียว แล้วเพิ่มได้หลาย SKU (สี/สต๊อก/รูปเฉพาะ SKU) ในฟอร์มเดียว
  - พิมพ์ Model ที่มีอยู่แล้ว → โหมด "เพิ่ม SKU เข้าสินค้าเดิม" อัตโนมัติ (ฟิลด์ร่วมล็อกตามของเดิม)
  - แก้ไข = แก้ไขทั้งกลุ่ม SKU ของ Model นั้น เพิ่ม/ลบ/แก้ SKU ได้อิสระในหน้าเดียว เปลี่ยนชื่อ Model ไม่ได้
  - ชื่อสินค้า (Product Name) สร้างอัตโนมัติจาก Model + สี ไม่ต้องพิมพ์เอง

- **นำเข้าสินค้าจากไฟล์ CSV**: ดูหัวข้อ "ตั้งค่าระบบ" (ใช้ปุ่ม "นำเข้า CSV" ในหน้าสินค้า); แก้ราคา/สต็อก/สถานะหลายรายการพร้อมกันได้จากปุ่มแก้ไขด่วน

## จัดการออเดอร์ (Orders)
- ตารางแอดมิน แสดงทุกคอลัมน์บนทุกอุปกรณ์ (เลื่อนแนวนอนได้)
- แก้ไขออเดอร์เต็มรูปแบบ (Admin), แก้ได้เฉพาะสถานะ (Manager)
- ระบบสต๊อกปรับอัตโนมัติตามการเปลี่ยนสถานะ/แก้ไข/ลบออเดอร์ พร้อม log ที่ InventoryLog
- พิมพ์ย้อนหลัง (reprint) ใบจองจากแถวออเดอร์ที่มีอยู่

## Dashboard
- KPI สรุปยอด, กราฟยอดขายรายวัน, วิเคราะห์ยอดตามโมเดลสินค้า (จัดกลุ่มด้วย Model เดียว ไม่แยกความจุ), ช่องทางขายตามสินค้า, 10 อันดับสาขา/พนักงานขาย, ตารางโปรโมชั่น/ของแถมยอดนิยม
- แบนเนอร์ Hero Banner (สไลด์พร้อมหัวข้อ+คำโปรยทับภาพ) และ Promo Grid บนหน้า Dashboard
- ป๊อปอัพโปรโมชั่นแสดงครั้งแรกของเซสชัน (รูป+หัวข้อ+คำอธิบาย+ปุ่ม CTA หรือรูปเปล่าถ้าไม่ตั้งค่าเพิ่ม)
- **ความเร็ว**: server แคชข้อมูลดิบ Dashboard 120 วินาที (Orders/Products/Members, ไม่มี Password; Sales กรองสาขาหลังแคช) และล้างแคชทุกครั้งที่มีการเขียนผ่านแอป; ปุ่ม "รีเฟรช" ข้ามแคช + แสดงเวลาของข้อมูล; โหลดอัตโนมัติทุก 30 วินาทีใช้แคชปกติ

## รายงาน (Reports)
4 หน้า จัดกลุ่มด้วย **Model อย่างเดียว** (ไม่แยกความจุ) ทุกหน้า:
- **สรุปยอดจองรายวัน** — ตาราง pivot ตามวันที่ + ตามสถานะจอง T/F + เทียบ % รายวัน/ตามกลุ่มรุ่น
- **สรุปยอดรุ่น/แอเรีย/ช่องทาง** — ยอดจองตามรุ่น×ช่องทาง, ตามสินค้า(รวมสี)×ช่องทาง, ตามแอเรีย×รุ่น
- **สรุปยอดจองตามสาขา** — 3 ตาราง (จอง T / จอง F / ผลรวม) กรองได้ตาม Area/สาขา
- **สรุปข้อมูลจองทั้งหมด** — โควต้า/ยอดจอง/คงเหลือต่อหมวดหมู่สินค้า
- **หน้า Target** — เป้าหมายเทียบยอดจองจริงตาม Area

ทุกตารางมีปุ่ม export เป็นรูปภาพ

## ใบเสนอราคา/ใบแจ้งหนี้ (Invoice)
- สร้าง/แก้ไข/อนุมัติเอกสาร (workflow: รออนุมัติ → อนุมัติแล้ว, เอกสารอนุมัติแล้วแก้ไม่ได้ยกเว้น Admin ลบได้)
- ข้อมูลบริษัท/โลโก้/ลายเซ็นผู้อนุมัติตั้งค่าล่วงหน้าได้ในหน้าตั้งค่าระบบ ดึงมาใช้อัตโนมัติทุกเอกสารใหม่
- พิมพ์เป็น PDF ผ่าน browser print (คงโทนขาวดำเป็นทางการ ไม่ใช้ธีมสีของแอป)

## จัดการเนื้อหา (เมนู ตั้งค่าระบบ → เนื้อหา, Admin เท่านั้น)
หน้าตาแบบ Otis CMS: ปุ่มเพิ่ม/ลบที่เลือก, กล่องค้นหาหลายช่อง, ตารางมีช่องติ๊ก/เลือกจำนวนแถว/ค้นหาด่วน/เรียงคอลัมน์/แบ่งหน้า/ป้ายสถานะ
- **จัดการแบนเนอร์**: Hero / Promo Grid / Popup ในตารางเดียว กรองตามประเภท สถานะ (แสดงอยู่/รอแสดง/หมดอายุ) และวันที่; เพิ่ม/แก้/ลบ, อัปโหลดรูป, ตั้งวันที่เริ่ม-สิ้นสุด (เวลาไทย)
- **จัดการข่าวสาร**: หมวดหมู่, หัวข้อ, รายละเอียด, รูป, ลิงก์, ลำดับ (Seq แก้ในตารางได้), สถานะ, วันที่เริ่ม-สิ้นสุด, ผู้สร้าง/ผู้แก้ไข — ชีต News/NewsCategories สร้างเองครั้งแรกที่เปิดหน้า; ข่าวที่เปิดใช้และอยู่ในช่วงวันที่ถูกส่งให้หน้าร้าน และแสดงบนหน้าร้านเป็นแถวการ์ดข่าว (เหนือชั้นยอดนิยม) กดเพื่ออ่านรายละเอียด/เปิดลิงก์
- **หมวดหมู่ข่าว**: ชื่อไม่ซ้ำ, เปลี่ยนชื่อแล้วข่าวตาม, ลบไม่ได้ถ้ายังมีข่าวในหมวด

## ตั้งค่าระบบ (Settings, Admin เท่านั้น)
- **ชื่อเว็บแอป + โลโก้**: เปลี่ยนชื่อ/อัปโหลดโลโก้แทนไอคอนเริ่มต้น แสดงผลหน้า Login/เมนูข้าง/เมนูมือถือ/ท้ายหน้า
- **ฐานข้อมูล**: Auto Setup (สร้างชีตครั้งแรก, ล็อกไม่ให้รันซ้ำโดยไม่มีสิทธิ์), Drive Folder ID สำหรับเก็บรูปอัปโหลด
- **ตั้งเวลารับจอง** (Booking Period): กำหนดช่วงวันที่เปิด/ปิดรับจองสินค้าหน้า POS
- **แบนเนอร์ (Hero / Promo Grid / Popup)**: ย้ายไปจัดการที่เมนู เนื้อหา → จัดการแบนเนอร์ แล้ว (ดูหัวข้อ "จัดการเนื้อหา") — แท็บเดิมในหน้าตั้งค่าถูกตัดออก ลิงก์/สิทธิ์เมนูเก่าส่งต่อไปหน้าใหม่อัตโนมัติ
- **พื้นหลังหน้า Login**: อัปโหลด/เปลี่ยนรูปพื้นหลัง พร้อมพรีวิว
- **ข้อมูลติดต่อร้าน**: เบอร์โทร / LINE (ID หรือลิงก์ https) / เวลาทำการ → แสดงที่ footer ทุกหน้า (คีย์ `ContactPhone`, `ContactLine`, `ContactHours` ในชีต Settings; ตรวจรูปแบบก่อนบันทึก, ช่องว่างจะไม่แสดง)
- **ข้อมูลบริษัท**: ชื่อ/ที่อยู่/อีเมล/โลโก้/ผู้อนุมัติ+ลายเซ็น สำหรับใบเสนอราคา/ใบแจ้งหนี้
- จัดการตารางอ้างอิงทั่วไป (Branches, Channels, Promotions, Interests, GiftMappings, AutoPromotions, Members) ผ่านฟอร์ม CRUD มาตรฐาน กันสร้างรหัสซ้ำทับข้อมูลเดิมทั้งฝั่งฟอร์มและฝั่ง server
- **นำเข้าข้อมูลจากไฟล์ CSV** (Admin): สินค้า / สาขา / ช่องทางขาย / สมาชิก — ปุ่ม "นำเข้า CSV" บนแต่ละหน้า, มีไฟล์ตัวอย่าง (CSV และ .xls ที่ตั้งเป็นข้อความ) กันเลขยาวกลายเป็น 8.65E+13, แสดงตัวอย่างผล (ข้ามรายการซ้ำ/รายงานแถวที่ผิด) ก่อนบันทึกจริง, เพิ่มเฉพาะรายการใหม่ ไม่เขียนทับ, ครั้งละไม่เกิน 1,000 แถว; สมาชิกที่ไม่ใส่รหัสผ่านระบบสุ่มให้และแสดงครั้งเดียว

## ความปลอดภัยที่มีอยู่แล้ว
Token bearer เซ็นด้วย HMAC (อายุ 30 วัน), รหัสผ่าน salted SHA-256, ตรวจสิทธิ์ตาม role ซ้ำฝั่ง server ทุก action, กัน SKU/ID ซ้ำทั้งฝั่งฟอร์มและ server, กัน formula injection ในช่องข้อความอิสระ, escape HTML ทุกจุดที่แสดงข้อมูลจาก sheet/ผู้ใช้, ราคา/สต๊อก/โปรโมชั่นตอน checkout อ่านจากชีตฝั่ง server เท่านั้นไม่เชื่อค่าที่ client ส่งมา

## หน้าตาและการพัฒนา (UI / Dev)
- **เมนูข้าง**: ป้ายสองบรรทัด (ไทยบน อังกฤษล่าง) เส้นนำทางสีส้มที่รายการที่เลือก, หัวหมวดแบบย่อ, การ์ดผู้ใช้ใบเดียวที่เปิดเมนู (โหมดมืด/เปลี่ยนรหัสผ่าน/ออกจากระบบ); เมนูมือถือยังเป็นแบบเดิม
- **Tailwind แบบ precompiled**: ไม่ใช้ CDN ตอน runtime แล้ว — CSS สร้างเป็น `src/TailwindCSS.html` (`npm run build:css`, ตั้งค่าที่ `tailwind.config.js` มี safelist สำหรับ class ที่ประกอบด้วยสตริง) ต้องรันใหม่ทุกครั้งที่เพิ่ม class ใหม่
- **ข้อควรระวัง GAS**: ตัวตัดคอมเมนต์ตอน serve ไม่รู้จักสตริง — ห้ามมี `/*` ในสตริงของ `<script>`, และ `//` (เช่น `https://...`) ใน template literal (backtick) จะตัดบรรทัดที่เหลือทิ้ง
- **ทดสอบ**: `npm test` (server ~151 ข้อ ด้วย gasmock + client ~150 ข้อ ด้วย Chrome headless) ก่อน `clasp push` ทุกครั้ง; `clasp push` ไม่เปลี่ยนสิ่งที่ผู้ใช้เห็น ต้อง `clasp deploy -i <deploymentId>` แยกต่างหาก

**ตั้งค่าระบบ (เพิ่มเติม)**: ค่าที่เป็นความลับ (Webhook URL, Drive Folder ID) ไม่ถูกส่งให้หน้าเว็บของ role ใดนอกจากหน้าตั้งค่าของ Admin และถูกซ่อนใน AuditLog; server ตรวจค่าทุกช่องตามกติกาต่อคีย์ (วันที่, ตัวเลข, https, อีเมล, เบอร์, LINE) และปฏิเสธคีย์/ประเภทที่ไม่รู้จักทั้งก้อน; การแก้/ลบแบนเนอร์ยืนยัน ID + ประเภทของแถวก่อนเสมอ กันเขียนทับใบอื่นเมื่อมีแอดมินหลายคน; ลิงก์แบนเนอร์ต้องเป็น http(s)

**ตัวอักษรและตาราง**: ฟอนต์ทั้งระบบเป็น Roboto (ไล่ต่อด้วย Helvetica/Tahoma/Arial สำหรับภาษาไทย), ตัวอักษรเทาพื้นฐานใช้ดำเข้ม (`--ink-2`, สเกล slate 500-700 ใน Tailwind), ตารางข้อมูลทุกหน้าใช้สไตล์ Otis (หัวพื้น #f3f6f9, เส้นแถวบาง, ไม่มีเส้นแนวตั้ง) ผ่านกฎกลาง `#page-content table` ใน CSS.html พร้อมโหมดมืด
