### H4 — การเก็บรหัสผ่านอ่อน
- ที่: `src/Code.js:253`, `602`, `669`
- ปัญหา: SHA-256 รอบเดียว + salt ค่าคงที่ในซอร์ส (salt เดียวกันทุกคน), ยังรับ hash แบบไม่มี salt และ plain text,
  รหัสใหม่ขั้นต่ำ 4 ตัว, token เดิมยังใช้ได้หลังเปลี่ยนรหัสผ่าน
- แก้: salt สุ่มต่อผู้ใช้ + วน hash หลายรอบ (รูปแบบ `v2$salt$hash`, ย้ายอัตโนมัติตอน login สำเร็จ),
  ขั้นต่ำ 8 ตัว, ใส่เวลาที่เปลี่ยนรหัสผ่านใน token เพื่อให้ token เก่าหมดสภาพ

### พบเพิ่มระหว่างแก้ (ยังไม่ได้แก้)

- `appsscript.json` ไม่มี scope `script.external_request` แต่โค้ดเรียก `UrlFetchApp.fetch` ตอนส่ง Webhook แจ้งใบจองใหม่ (error ถูกกลืนใน `try/catch`)
  ถ้าบนเว็บจริงไม่เคยได้รับแจ้งเตือน Webhook นี่น่าจะเป็นสาเหตุ — ยืนยันจากโค้ดเท่านั้น ยังไม่ได้ดูบนเว็บจริง การเพิ่ม scope ทำให้ผู้ deploy ต้องกดอนุญาตสิทธิ์ใหม่
- scope `userinfo.email` ไม่มีโค้ดใช้แล้ว (ตัวที่ใช้คือฟังก์ชัน migrate ที่ลบไปในเฟส 1) เอาออกได้
- หน้าเว็บเดิมไม่มีการจัดการ token หมดอายุเลย (ผู้ใช้เห็นแต่ error จนกว่าจะกดออกจากระบบเอง) — แก้ไปพร้อมเฟส 4

### สิ่งที่ต้องทำตอน deploy (ตามลำดับ)

1. `clasp push` แล้ว `clasp deploy -i <deploymentId>` ของ deployment ที่ใช้งานจริง
2. เปิดเว็บในแท็บใหม่ ตรวจว่าหน้าแรกขึ้น, login ได้, กราฟแดชบอร์ดและกล่องข้อความขึ้นปกติ (ยืนยันว่า integrity ของสคริปต์ CDN ผ่านใน iframe ของ GAS)
   และตรวจ HTML ที่ GAS ส่งจริงตามวิธีใน `CLAUDE.md` (ตัวลบ comment)
3. จับเวลา login 1 ครั้ง — hash แบบใหม่วน 2000 รอบ ยังไม่เคยวัดบน GAS จริง ถ้าช้าเกินรับได้ให้ลด `PW_V2_ROUNDS_`
4. ลบ Script property `MPOS_SECRET_KEY` (หมุนคีย์ — ทุกคนต้อง login ใหม่) เพราะไม่รู้ว่าคีย์เคยถูกดึงออกไปก่อนแก้หรือยัง
5. Admin ทุกคนเปลี่ยนรหัสผ่าน (อย่างน้อย 8 ตัว)
6. ดู AuditLog ย้อนหลังหา action ที่ผิดปกติ (แก้สมาชิก, เปลี่ยนตั้งค่า, ลบข้อมูล ในเวลาที่ไม่มีใครทำ)

ผลกระทบที่ผู้ใช้จะเห็นหลัง deploy: ทุกเครื่องที่ login ค้างไว้ถูกพากลับหน้า login หนึ่งครั้ง, ลูกค้าที่เปิดลิงก์ติดตามใบจองต้องกรอกเบอร์ 4 หลักท้ายทุกครั้ง,
ใบจองที่ไม่ได้บันทึกเบอร์โทรเปิดจากหน้าติดตามสาธารณะไม่ได้, รหัสผ่านใหม่ต้องยาวอย่างน้อย 8 ตัว (รหัสเดิมที่สั้นกว่ายัง login ได้)
