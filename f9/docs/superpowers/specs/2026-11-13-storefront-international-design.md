# f9 หน้าร้าน: ยกระดับให้ดูเป็นเว็บ e-commerce ระดับสากล

วันที่ 2026-11-13 · สถานะ: รออนุมัติ

## ทำไม

หน้าร้าน f9 มีโครงสร้างของเว็บขายของครบแล้ว (header, เมนูหมวด, ตัวกรอง, การ์ดสินค้า, หน้ารายละเอียด, ตะกร้า, footer) แต่ภาพรวมยังดูเป็น "แอปภายใน" มากกว่าร้านค้าออนไลน์ระดับสากล งานนี้คือการขัดเกลาหน้าตาและลำดับการใช้งานของหน้าร้าน โดยไม่เปลี่ยนระบบหลังบ้านและไม่เปลี่ยนขั้นตอนธุรกิจ

เจ้าของงานมอบการออกแบบให้ผู้พัฒนาตัดสินใจ ทุกข้อในเอกสารนี้จึงเป็น **ข้อเสนอของผู้ออกแบบ** ยังไม่ใช่สิ่งที่เจ้าของงานยืนยัน ยกเว้นเป้าหมายหลัก "ดูเป็นมืออาชีพแบบเว็บ e-commerce international"

## สิ่งที่เห็นจากหน้าจอปัจจุบัน

ดูจาก `tests/out/pos-desktop.png`, `pos-mobile.png`, `pos-detail-page.png`, `pos-checkout.png`, `footer-desktop.png`

1. **สีส้มถูกใช้มากเกินไป** ปุ่มตะกร้าใน header เป็นส้มทึบ และการ์ดทุกใบมีปุ่มส้มเต็มความกว้าง หน้าจอเดียวมีก้อนส้ม 9 ก้อนขึ้นไป สายตาไม่รู้ว่าอะไรสำคัญ เว็บสากลใช้สีเน้นกับ "การกระทำหลักหนึ่งอย่างต่อหน้าจอ"
2. **รูปทรงเป็นแคปซูลแทบทุกชิ้น** ปุ่ม ช่องค้นหา dropdown ป้าย ชิป มุมโค้ง 999px ทั้งหมด (35 จุดใน `CSS.html`) ทำให้ดูเป็นแอปมือถือเล่น ๆ มากกว่าร้านค้า
3. **มือถือ: กว่าจะเห็นสินค้าต้องเลื่อนไกล** ลำดับคือ แถบ Pre Booking → แบนเนอร์ → คูปอง → ดูล่าสุด → แบรนด์ → ข่าว → สินค้า และแถบเปรียบเทียบลอยทับเนื้อหา ปุ่มตะกร้าใน header ใหญ่เกิน
4. **หัวข้อ section ใช้ขีดส้มนำหน้า + คำอธิบายต่อท้ายบรรทัดเดียว** ดูแน่นและไม่มีจังหวะ
5. **ขั้นตอนสั่งจองเป็น popup แน่น ๆ** กรอบซ้อนกรอบ สีพื้นหลายสี (เขียว แดง ฟ้า) ในฟอร์มเดียว และจบด้วย popup ไม่มีหน้ายืนยันคำสั่งจองที่ชัดเจน
6. **ไม่มีสถานะระหว่างโหลด** GAS โหลดช้า 2-4 วินาที ผู้ใช้เห็นหน้าว่าง
7. **องค์ประกอบสร้างความเชื่อมั่นมีน้อย** ไม่มีหน้า "วิธีการจอง", คำถามที่พบบ่อย, หน้าสาขา footer มีแค่ลิงก์พื้นฐาน
8. **มีภาษาไทยอย่างเดียว**

## เป้าหมาย

- คนที่เปิดหน้าร้านครั้งแรกรู้สึกว่าเป็นร้านค้าออนไลน์ที่น่าเชื่อถือ เทียบได้กับเว็บร้านมือถือแบรนด์ใหญ่
- หน้าจอหนึ่งมีปุ่มหลักสีส้มหนึ่งปุ่ม ที่เหลือเป็นปุ่มรอง
- มือถือเห็นสินค้าใบแรกภายในการเลื่อนไม่เกินหนึ่งหน้าจอครึ่ง
- ขั้นตอนสั่งจองอ่านง่าย เป็นขั้น ๆ และจบที่หน้ายืนยันที่มีเลขใบจอง

## ไม่ทำในงานนี้

- ระบบชำระเงินออนไลน์, บัญชีลูกค้า/สมัครสมาชิก, รีวิวสินค้า
- ออกแบบหลังบ้านใหม่ (dashboard, ตาราง, รายงาน)
- SEO และภาพตัวอย่างเวลาแชร์ลิงก์ ทำไม่ได้บน Google Apps Script (หน้าเว็บอยู่ใน iframe ของ Google, URL เป็น `script.google.com`) ถ้าต้องการโดเมนของตัวเองต้องย้ายหน้าบ้านออกจาก GAS ซึ่งเป็นโครงการแยก
- เปลี่ยนโครงสร้างชีต `Orders` หรือขั้นตอนธุรกิจการจอง

## สิ่งที่ถือว่าล้มเหลวแม้จะสวย

- พนักงานขายจองให้ลูกค้าช้าลงกว่าเดิม (จำนวนคลิกเพิ่ม หรือหาช่องกรอกยากขึ้น)
- ช่องข้อมูลจองหายหรือการตรวจสอบฝั่ง server ถูกลดลง
- โหมดมืดพัง หรือลิงก์ `?p=` / `?track=` เดิมใช้ไม่ได้
- หน้าขาวบน GAS จาก `/*` หรือ `//` ใน string

## แนวทางการออกแบบ

### 1. ระบบพื้นฐาน (design tokens)

กำหนดเป็นตัวแปร CSS ชุดเดียวในบล็อกใหม่ท้าย `CSS.html` แล้วให้ส่วนหน้าร้านอ้างตัวแปรนี้

| เรื่อง | ค่า |
|---|---|
| มุมโค้ง | ปุ่ม/ช่องกรอก 8px · การ์ด/กล่อง 12px · หน้าต่าง 16px · แคปซูลเหลือเฉพาะชิปตัวกรองและป้ายจำนวน |
| ระยะห่าง | สเกล 4/8/12/16/24/32/48/64 · ระยะระหว่าง section 48px (มือถือ 32px) |
| ตัวอักษร | สเกล 12/14/16/20/24/32 · หัวข้อ section 20-24px หนา 600 ไม่มีขีดสีนำหน้า · คำอธิบายขึ้นบรรทัดใหม่สีเทา |
| สี | ส้ม `#FF6B00` เฉพาะปุ่มหลัก ลิงก์ และสถานะเลือก · กรมท่า `#0f2a43` ป้ายสถานะ · แดง `#E11D48` ส่วนลดเท่านั้น · พื้นขาว พื้นรอง `#F5F5F7` · เส้นขอบ `#E5E7EB` |
| เงา | สองระดับเท่านั้น: การ์ดตอน hover และหน้าต่างลอย การ์ดปกติใช้เส้นขอบ ไม่ใช้เงา |
| การเคลื่อนไหว | 150-200ms ease-out, เคารพ `prefers-reduced-motion` |
| ปุ่ม | สามแบบ: หลัก (ส้มทึบ), รอง (ขอบเทา พื้นขาว), ข้อความ (ลิงก์) สูง 44px บนมือถือ |
| โฟกัส | วงโฟกัส 2px ชัดเจนทุกองค์ประกอบที่กดได้ |

กฎสีเดิมใน CLAUDE.md (สีเรียบ ไม่มี gradient) ยังใช้ต่อ

### 2. Header

- ปุ่มตะกร้าเปลี่ยนจากแคปซูลส้มเป็นไอคอน + ป้ายจำนวนสีส้มเล็ก ๆ (แบบเดียวกับรายการโปรด)
- ช่องค้นหามุม 8px พื้น `#F5F5F7`
- ตัวเลือกช่องทาง/สาขาย้ายขึ้นแถบบนสุด (`#sfTopbar`) เป็นข้อความ "รับที่: สาขา… ▾" แถวเมนูหมวดจึงเหลือแต่เมนู
- มือถือ: โลโก้ · ค้นหา (ไอคอนกดแล้วขยาย) · ตะกร้า · บัญชี ในแถวเดียวสูง 56px ช่องทาง/สาขาเป็นแถบบางใต้ header

### 3. หน้าแรกและรายการสินค้า

- ลำดับใหม่: แบนเนอร์หลัก → หมวด (มือถือ) → ยอดนิยม → สินค้าทั้งหมด → คูปอง/ข่าว → ดูล่าสุด แถบ "Pre Booking เปิดรับจองถึง…" ย่อเป็นแถบประกาศบาง ๆ บนสุด
- แบนเนอร์หลักเต็มความกว้างเนื้อหา อัตราส่วนคงที่ (เดสก์ท็อป 21:9, มือถือ 4:3) กันหน้ากระตุกตอนรูปโหลด
- แถบเปรียบเทียบไม่ลอยทับเนื้อหา: ย่อเป็นปุ่มลอยมุมล่าง "เปรียบเทียบ (2)" กดแล้วเปิดรายการ
- ตัวกรองด้านข้างคงเดิม ปรับระยะและเส้นแบ่ง มือถือเปิดเป็นแผ่นเลื่อนจากล่างพร้อมปุ่ม "ดูสินค้า N รายการ"
- แถบเหนือรายการ: จำนวนผลลัพธ์ทางซ้าย, ชิปตัวกรองที่เลือกอยู่ (กดลบได้), เรียงตามทางขวา

### 4. การ์ดสินค้า

- รูป 1:1 บนพื้น `#F5F5F7` มุม 12px, `object-fit: contain`, โหลดแบบ lazy
- ทั้งการ์ดกดได้ เปิดหน้ารายละเอียด **เอาปุ่มส้ม "จองเลย" ออกจากการ์ด** เดสก์ท็อปแสดงปุ่มรอง "ดูรายละเอียด" ตอน hover, มือถือไม่มีปุ่ม (นี่คือการลดสีส้มที่ได้ผลมากที่สุด)
- ลำดับข้อความคงเดิม (แบรนด์ → ชื่อ → สี/ความจุ → ราคา → โปรฯ → สต็อก) ปรับขนาด: ราคา 20px หนา 700, ราคาเดิมขีดฆ่าเทา, "ประหยัด" เป็นข้อความแดงไม่มีพื้น
- ป้ายส่วนลด/NEW มุม 6px ขนาดเล็กลง อยู่มุมซ้ายบนที่เดียว
- คง id และข้อความที่ test ใช้ (`cardHtml`, ชื่อหมวด ฯลฯ) ถ้า test ใดกดปุ่ม "จองเลย" ให้ปรับ test ไปกดการ์ดแทน

### 5. หน้ารายละเอียดสินค้า

โครงปัจจุบันดีแล้ว ปรับเฉพาะ:

- ตัวเลือกความจุ/สีใช้กรอบ 8px, ตัวที่เลือก = ขอบกรมท่า 2px พื้นขาว (ไม่ทึบ) สีแสดงจุดสีจริงคู่ชื่อ
- แถวความเชื่อมั่นใต้ราคา 3 ข้อ (ของแท้ประกันศูนย์ · ล็อกราคา · รับของแถม) เป็นไอคอน + ข้อความ ไม่มีกรอบ
- ปุ่ม "ออกใบเสนอราคา" เป็นปุ่มรอง, ปุ่มส้มมีปุ่มเดียวคือ "เพิ่มลงตะกร้า"
- สินค้าใกล้เคียง (รุ่นเดียวกันใน Series) ท้ายหน้า ใช้การ์ดเดียวกับหน้ารายการ

### 6. ตะกร้าและขั้นตอนสั่งจอง

- `#checkoutModal` เปลี่ยนเป็นหน้าเต็มจอแบบเดียวกับหน้ารายละเอียด (คง id เดิมและ id ช่องกรอกทั้งหมด เปิด/ปิดผ่าน `showModal`/`hideModal` เหมือนเดิม)
- ซ้าย: ฟอร์มแบ่ง 3 ตอนมีหัวข้อเลขกำกับ (1 ข้อมูลลูกค้า · 2 เงื่อนไขและมัดจำ · 3 ความสนใจลูกค้า) อยู่หน้าเดียวเลื่อนลง ไม่แบ่งเป็นหลายหน้า เพื่อไม่ให้พนักงานคลิกเพิ่ม
- ขวา (เดสก์ท็อป, ติดขอบบน): สรุปรายการ ของแถม ส่วนลด ยอดรวม ช่องยอมรับเงื่อนไข และปุ่มยืนยัน มือถือ: สรุปพับได้ด้านบน ปุ่มยืนยันติดขอบล่าง
- เลิกใช้พื้นสีหลายสีในฟอร์ม เหลือพื้นขาว เส้นแบ่ง และข้อความแจ้งข้อผิดพลาดใต้ช่อง
- หลังสั่งจองสำเร็จ: หน้ายืนยัน แสดงเลขใบจอง สรุปรายการ ปุ่ม "คัดลอกลิงก์ติดตาม" และ "กลับหน้าร้าน" แทน popup

### 7. ความเชื่อมั่นและเนื้อหา

- Footer: เพิ่มคอลัมน์ "ช่วยเหลือ" (วิธีการจอง · คำถามที่พบบ่อย · สาขาของเรา) และแถวช่องทางผ่อน/ชำระเป็นข้อความ
- หน้าเนื้อหาใหม่ 3 หน้า เปิดเป็นหน้าเต็มจอแบบเดียวกับ `openPolicy`: วิธีการจอง (3 ขั้น), คำถามที่พบบ่อย, สาขา (จากชีต `Branches` ที่มีอยู่)
- ข้อความ "วิธีการจอง" และ "คำถามที่พบบ่อย" แก้ได้จาก Settings (key ใหม่ `HelpHowTo`, `HelpFaq` ต้องเพิ่มใน `SETTING_RULES_`) มีค่าเริ่มต้นในโค้ด

### 8. สถานะโหลด / ว่าง / ผิดพลาด

- โครงร่างสีเทา (skeleton) ของ header, แบนเนอร์ และการ์ด 8 ใบ ระหว่างรอ `GET_ALL_DATA`
- หน้าว่างของผลค้นหา ตะกร้า รายการโปรด: ไอคอนเส้น + หนึ่งประโยค + ปุ่มรองหนึ่งปุ่ม
- ข้อความแจ้งเตือน (toast) รูปแบบเดียวทั้งหน้าร้าน มุมล่างกลาง

### 9. สองภาษา ไทย/อังกฤษ (ตัวเลือก ทำท้ายสุด)

- ปุ่มสลับ TH/EN ที่แถบบนสุด จำค่าใน `localStorage`
- แปลเฉพาะข้อความของหน้าร้าน (ปุ่ม หัวข้อ ป้าย ข้อความแจ้ง) ผ่านตารางคำ `window.app.t(key)` ชื่อสินค้า โปรโมชัน และข้อความจากชีตไม่แปล หลังบ้านไม่แปล
- เป็นงานใหญ่ที่สุดในแผน (แตะข้อความเกือบทุกจุดใน `JS_Pos.html` 3,800 บรรทัด) ควรตัดสินใจแยกว่าจะทำหรือไม่

- อัตราส่วนแบนเนอร์หลัก 21:9 / 4:3 — แบนเนอร์ที่อัปโหลดไว้จะถูกครอบตัดใหม่ ต้องรู้ขนาดรูปที่ร้านใช้จริงก่อน
- ชิปตัวกรองที่เลือกอยู่เหนือรายการ และแผ่นตัวกรองเลื่อนจากล่างบนมือถือ

## ข้อจำกัดที่ผู้ทำต้องรักษา

- ห้ามมี `/*` ใน string และห้ามมี `//` ใน template literal ของ `<script>` ใด ๆ
- เพิ่ม/เปลี่ยน class ของ Tailwind แล้วต้อง `npm run build:css` และ commit `TailwindCSS.html`
- องค์ประกอบที่สลับด้วย `.hidden` กำหนด `display` ผ่าน `:not(.hidden)` เท่านั้น
- CSS ที่เขียนสีตรง ๆ ต้องมีกฎ `html.dark` คู่กัน
- ข้อความจากชีตผ่าน `esc()` / `escAttrJs()` / `safeRichText` ทุกจุด
- คง id ขององค์ประกอบและชื่อ route เดิม, ลิงก์ในหน้าเป็น `#id` ธรรมดา
- อัปเดต `CLAUDE.md` เมื่อโครงสร้างหน้าร้านเปลี่ยน
- ไม่ `clasp push` / `clasp deploy` จนกว่าเจ้าของงานสั่งแยกเป็นครั้ง ๆ และตรวจผลบน deployment จริงในแท็บใหม่ (ตัวตัดคอมเมนต์ของ GAS ทดสอบในเครื่องไม่ได้)

## ปล่อยให้ผู้ทำตัดสินใจ

- ชื่อ class และการจัดบล็อกใน `CSS.html`
- รายละเอียด skeleton และไอคอนของหน้าว่าง
- จะย้ายกฎเก่าที่ถูกทับไปลบทิ้งหรือปล่อยไว้ (แนะนำลบเมื่อแน่ใจว่าไม่มีที่ใช้)
